# 架构总览

> 文档首页：[`index.md`](index.md) › 入门

本页说明系统组件划分、职责边界、数据流，以及关键设计决策。

## 组件与职责

```
┌─────────────┐   HTTP (JSON, 令牌)   ┌──────────────────┐
│  前端(浏览器) │ ─────────────────────▶ │  后端 Spring Boot  │
└─────────────┘                       │  · 登录/认证/授权  │
                                       │  · 请求编排       │
                                       │  · 持久化(账户/授权)│
                                       └────────┬─────────┘
                                                │ RestClient
                                                │ X-Shared-Secret（机器级认证）
                                                │ 仅本机回环 127.0.0.1:8090
                                                ▼
                                       ┌──────────────────┐
                                       │  模组本地数据 API   │
                                       │  · 库存快照读取     │
                                       │  · 合成命令接收     │
                                       └────────┬─────────┘
                                                │ 主线程调度，不跨线程碰世界
                                                ▼
                                       ┌──────────────────┐
                                       │ Minecraft 服务端   │
                                       │  (AE2 网络/合成)   │
                                       └──────────────────┘
```

| 组件 | 负责 | 明确不负责 |
| --- | --- | --- |
| 模组 | 唯一读写游戏内 AE2 状态；暴露仅供本机调用的数据 API | 网页渲染、账号认证、会话管理 |
| 后端 | Web API、登录/授权、持久化、把网页请求转发给模组 | 接触 Minecraft/AE2 类、任何游戏线程调度 |
| 前端 | UI 渲染、库存/合成展示、只与后端通信 | 直连 MC 服务器或 AE2、自己承担授权 |
| 契约 | 定义模组↔后端交换数据的版本化 schema | 放置任何一方的实现代码 |

**关键边界**：模组与后端各自独立实现同一份契约，双方都不依赖对方的内部类。

## 数据流

1. 前端登录后端，获得会话令牌，后续请求携带该令牌。
2. 后端校验令牌与授权（该用户能访问哪些 `networkAccessId`）。
3. 后端通过 `RestClient` 调用模组的本机 API（`X-Shared-Secret` 头做机器级认证），读取已缓存的库存/合成状态或提交合成命令。
4. 模组只在主线程内读写 AE2 状态，定时（如 4 秒）把状态快照放入只读缓存区供后端读取。
5. **实时推送（2026-11）**：后端每 2s 拉模组网格列表与内存指纹比对，变化即通过 SSE（`GET /api/events`）广播变更提示给前端；前端收到后 refetch，原有 5s/10s 轮询保留作兜底（详见 `docs/contracts/web-api.md` v0.4；roadmap 已完成项）。

## 关键设计决策

> 已定稿的完整方案（控制器锚点身份、快照缓存、命令队列、契约形状）见 [技术设计](design.md)，本表为摘要。

| 决策 | 内容 | 理由 |
| --- | --- | --- |
| 线程安全 | 所有触碰 AE2/世界状态的逻辑必须通过 `MinecraftServer#execute` 调度到主线程；HTTP/定时线程绝不直接访问世界 | 从独立线程访问世界会导致死锁 |
| 缓存快照 | 复用 AE2 的 `getCachedInventory()`（每 tick 至多更新一次），主线程周期性把结果序列化到线程安全的只读区 | 复用 AE2 缓存、避免自造轮子，降低网页并发对游戏的拖累 |
| 合成命令 | Web 侧只写命令队列，主线程消费队列并调用合成 API | 提交合成必须在服务器 tick 线程 |
| 存档内专属 ID | 用挂在 Overworld 的 `SavedData` 维护 `networkAccessId → 位置/状态/令牌` 映射，方块 NBT 只存 UUID 引用 | 跨会话持久、与坐标解耦、方块拆毁后可标记失效 |
| 方块不加载区块 | 方块节点 inactive 时写入离线标记，网页据此显示「数据截至」，而非静默返回旧数据 | 符合「网络运作时才运作」 |
| 后端↔模组通信 | 模组只暴露 127.0.0.1 本机端点 + 共享密钥，由后端统一对外 | 认证/会话集中在后端，游戏进程内几乎无并发与请求解析开销 |
| 依赖精简 | 后端不引 Servlet 容器之外的重量级中间件；账号/授权用嵌入式 H2 | 数据量小，避免过度设计 |

## 当前实现状态

| 组件 | 状态 |
| --- | --- |
| 模组 | 已实现接入方块（GUI：状态实时刷新、身份信息展示、displayName 改名）、控制器定位、Overworld 身份表、4 秒快照、只读查询 API 和合成命令队列；样板列表仅完成声明/持久化框架；**客户端图标导出（模组部分）已实现**：`IconService` 离屏渲染 16×16 PNG + 本地 API `GET /icons/{ns}/{path}.png` 静态服务（专用服务器无客户端，图标回退占位） |
| 后端 | 分层骨架 + P1/P2 转发已实现（网格列表、快照、合成命令的透传与错误翻译，RestClient 带 2s/5s 超时）；P3 账号认证已实现（Sa-Token + H2 账户表，`/api/**` 除登录端点全部要求登录）；v0.3 网格密码访问控制 + v0.4 实时推送（SSE）已实现；v0.5 全站术语统一为 grid（`/api/networks`→`/api/grids`、`Grid*` 类）；v0.6 `nameKey` 透传 + v0.7 图标字节转发（`/api/icons`，纯代理不自建缓存）已实现 |
| 契约 | 初版本机 API 与 Web API v0.7（含认证端点、网格访问控制、SSE 实时事件、`nameKey`、图标转发）已记录并实现；完整 JSON Schema/OpenAPI 待定义 |
| 前端 | 登录页 + 选择页 + 详情页完成；未登录自动跳登录页，登出立即回登录页；`VITE_USE_MOCK=false` 时走后端真实请求（dev 需 Vite `/api` 代理）；选择页/详情页订阅 SSE 事件即时刷新，轮询兜底；物品格已接模组导出图标（懒加载 + 失败回退占位） |
